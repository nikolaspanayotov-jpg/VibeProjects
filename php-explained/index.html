What does the desk represent?

The desk is temporary memory. Folders are data structures, and the sticky note is a reference to a location in memory. PHP’s underlying code follows these references. Reading unfinished data or following a reference after its target has been released can send it down an unintended path.

What changed inside PHP?

The out-of-memory repair replaces an abrupt escape from an operation with a controlled stop at a safe execution point, or an immediate process exit at a higher memory threshold. The stale-state repairs fix the lifecycle of retained request references. Both changes keep invalid data out of later operations. Read the technical advisories.

The backstage, explained

One request. A little work. A clean desk.

A server receives your request, prepares a response and sends it back. PHP is the software many websites use to do that work.

You ask for something

You open a page or submit a form. Your browser sends a message called a request.

A worker uses a desk

A server worker handles the request. Temporary memory holds the information it needs along the way.

The desk gets cleared

The response goes back. PHP releases the temporary memory, and the worker can move on to another request.

The rule at the heart of both stories: use data only when it is ready, and stop using it when its memory has been released.

Why it matters

From a memory mistake to an attacker’s instructions.

Researchers showed that carefully arranged memory could turn these bookkeeping errors into remote code execution.

How does the mistake become an attack?

A memory mistake can stop a job. An attacker’s aim is to arrange the data so that the same mistake redirects what the worker does.

  1. A request hits the bug

    PHP reaches unfinished data or an outdated reference.

  2. The wrong data is used

    The worker tries to use information that is unfinished or no longer valid.

  3. The worker may crash

    The request can fail and the worker can stop. A crash interrupts the job.

A failure interrupts the job.A memory error can cause a crash. Turning it into control takes more preparation.

Where does the login screen fit?

In the demonstrated Apache/mod_php setup, PHP could reach the flaw before the website checked an account or password. Follow the request to see why.

The login check comes later.

PHP can process some incoming data before the application reaches its login checks. That earlier processing is where the demonstrated attack could reach the memory flaw.

What is remote code execution?

An outsider sends messages over the network that make the server run instructions they chose. “Unauthenticated” means they can do it without an account or password.

What could the attacker do?

The attacker’s code runs with the PHP worker’s permissions. That can allow access to data and secrets, changes to a website, or interruption of its services. The worker’s permissions and isolation determine the attacker’s reach.

How can it happen before a login?

PHP processes some request data before the website’s own code runs. Researchers demonstrated this route in Apache’s mod_php setup: the memory mistake happens before the application reaches its login checks.

Story one / CVE-2026-109618
Unfinished data gets trusted.

Work stops halfway through preparing data. Cleanup then acts on that unfinished data as though it were valid.

Story two / CVE-2026-109619
An outdated reference gets used.

PHP releases a request’s memory but keeps a reference to it. A later request on the same worker follows the old reference.

What to do

Repair the engine behind the website.

PHP sits underneath applications such as WordPress, Drupal and Joomla. Updating that runtime is the key repair for the two 21 October flaws.

Why does the PHP update matter?

PHP is the engine beneath the application. The hosting provider updates that engine separately from themes, plugins and the content management system. Ask about the PHP runtime serving your site, including any containers and additional workers.

How do vendor packages and temporary measures fit in?

Some vendors backport security repairs into their existing PHP packages. Your provider can confirm which fixes are installed. Configuration measures can block particular attack paths while administrators arrange the full update; the PHP advisories explain those paths and the settings involved.

The 23 October follow-up

A separate session upload progress issue.

CVE-2026-115560 concerns an unusual combination of session configuration and application behaviour. It involves changing the session serialisation handler at runtime while session upload progress remains enabled.

PHP’s 23 October advice is to disable session.upload_progress.enabled until the next regular bugfix release. Applications that keep the same serialisation handler at runtime can keep the feature enabled. Read the follow-up advisory.

A small glossary

Server: a computer that answers requests. Runtime: the software that runs application code. Worker: a process doing server tasks. Memory: temporary working space. Reference or pointer: a way to locate data in memory. Use-after-free: using memory after it has been released. Patch: a software repair. CVE: an identifier for a publicly tracked security flaw. Backport: a repair applied to an older software branch.
